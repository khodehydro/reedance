# دستور کار ایجنت Android — اتصال CMS به اپ بومیِ موجود

**این پروژه را از صفر در `android/` همین مخزن نساز.** شاخهٔ واقعی [`khodehydro/reedance-android/arena/f7c293e1-reedance-android`](https://github.com/khodehydro/reedance-android/tree/arena/f7c293e1-reedance-android)، snapshot [`894a4609`](https://github.com/khodehydro/reedance-android/commit/894a4609d35eee0ec7fd6b33c96ffc5ddb1414a5)، یک پروژهٔ مستقل Kotlin/Jetpack Compose با Room، Media3، WorkManager، installer امضاشده/محلی، starter و UI واقعی است. کد inspect شده، **build/device test آن در این کار اجرا نشده** و release guard بسته است. ماموریت تو: در **همان repo Android و شاخهٔ مربوط به خودت** اتصال [CATALOG_V1.md](CATALOG_V1.md) و [`contracts/catalog/v1`](../../contracts/catalog/v1/) به این مسیر فعلی؛ فرمت [`PACKAGE_V1.md`](PACKAGE_V1.md) و [`contracts/v1`](../../contracts/v1/) را بی‌هماهنگی عوض نکن. CMS فقط metadata/URL می‌دهد، فایل بسته/کاور از **هاست مالک** مستقیم دریافت می‌شود.

## نقشهٔ تغییر بر مبنای کد بررسی‌شده

| وضعیت فعلی در Android | اقدام لازم |
| --- | --- |

| `ui/Catalog.kt::CoverImage(id)` فقط drawableهای hardcoded (مانند `gulum-2`) را می‌شناسد؛ `Settings.kt` زبان‌های `en/es/ko/tr` را hardcode می‌کند. | کارت جدید از metadata امضاشده: عنوان/هنرمند/سطح/مدت، نصب‌شده از lesson معتبر. `coverUrl` اختیاری را فقط **مستقیم از هاست مالک** با HTTPS، host allowlist، redirect همان origin، سقف بایت/ابعاد، decode در IO، cache محدود و placeholder استفاده کن؛ تصاویر هرگز از Worker/proxy گرفته نشوند. `access=paid`/اشتراک از CMS v1 نیاید. UI زبان‌ها را از index معتبر و تقاطع با `SUPPORTED_TARGET_LANGUAGES`/schema و محتوای Starter واقعی نشان بده؛ زبان جدید ناشناخته را hide کن، نه crash. |

**رگرسیون UI/آفلاین ممنوع:** اتصال CMS نباید اسپلش با لوگوی اصلیِ وسط و متن دقیق `HYDRO team` پایین وسط (در محدودیت Android 12+ با صفحهٔ برند کوتاه پس از splash سیستم)، استارتر محلی، آزمون چهارقالبیِ مستقل، لایتنر/نشان‌ها، پخش Media3 و تنظیمات فارسی/انگلیسی/RTL-LTR را حذف کند. دادهٔ آموزشی فقط از lesson نصب‌شده و معتبر است، نه عنوان کاتالوگ. اگر شاخهٔ Android فعلی بعضی جزئیات برند را ندارد، آنها را در آزمون UI/device گزارش و تکمیل کن؛ ادعای اجرا بدون آزمون نکن.

**اختلاف مهم زبان:** schemaهای `contracts/v1/lesson`/manifest در مرجع فقط `en/es/ko` هستند، ولی Android runtime و (طبق `docs/interop/ANDROID_INSTALLER.md`) desktop از `tr` با extension استفاده کرده‌اند. پیش از publish `tr` یا زبان نو، schema و fixture/validatorهای دو تیم را هماهنگ و نسخه‌دار کن؛ بدون این کار وجود گزینهٔ tr/بستهٔ bundled گواه سازگاری شبکه/قرارداد نیست. افزودن **آهنگ** en/es/koِ سازگار به کاتالوگ APK نمی‌خواهد؛ افزودن **زبان** یا key/pack schema ناشناخته ممکن است بخواهد. زبان رابط (`fa/en`) مستقل از زبان مقصد است.

## الگوریتم شبکه و امنیت (از API تا پلیر)

1. از URL ثابت public CMS و پین raw32 `catalogKeyId` در پیکربندی release، فقط `GET` HTTPS دو endpoint مشخص را بزن. URLهای تست `example.invalid`/public key `cat-test-v1` نباید در release باشند؛ اگر config معتبر نیست، release fail کند. `If-None-Match` را فقط در کنار **body محلی از پیش تأییدشده** نگه دار. بار اول بدون cache: GET کامل؛ ۳۰۴ بدون body معتبر → fetch بدون شرط یا خطا. `Cache-Control:no-cache` دستی با Worker هماهنگ باشد. محدودیت ۱۹۲KiB envelope و ۱۲۸KiB decoded payload، timeout، redirect همان origin و error state روشن.
2. envelope JSON strict (کلید تکراری/UTF-8 خراب/field ناشناخته رد) → Base64URL canonical → Ed25519 روی `REEDANCE-CATALOG-V1\n<catalogKeyId>\n<raw payload>` **پیش از parse payload** → schema بر اساس endpoint (`languages`/`songs`) → route `language`، `targetLanguage`، ID یکتا، sort/order و host/URL policy را validate. manifest عمومی از همین URL استخراج شده ولی **هرگز به اعتبار امضای کاتالوگ به‌تنهایی اعتماد نکن**. کلید کاتالوگ از Worker secret به Android دانلود نمی‌شود؛ public key pin داخل APK است.
3. snapshot تأییدشده را با ETag، revision و SHA-256 decoded payload **اتمیک** در storage خصوصی برای هر endpoint نگه دار. revision کمتر یا همان revision با payload دیگر را رد کن؛ در خطای شبکه/دادهٔ نامعتبر/`1027` Cloudflare، cache قدیمی معتبر و نصب‌ها با هشدار قابل استفاده‌اند. پاک‌شدن آهنگ از CMS فایل/نشان/مرور کاربر را پاک نمی‌کند. تغییر زبان، snapshot زبان مربوط را تازه می‌گیرد ولی startup منتظر fetch نمی‌ماند.
4. روی tap آهنگِ نصب‌نشده، WorkManager با songId کار می‌کند و entry را از cache معتبرِ زبان مربوط دوباره resolve می‌کند. از هاست مالک `latest.json` با HTTPS/allowlist (پیکربندی trusted)، کنترل امضای *ناشر* `sig-`، songId/targetLanguage و ضدrollback می‌گیرد؛ سپس `.rdpack` را همان origin با basename امضاشده به private `.part`، hash/طول/GCM/ZIP/schema/media و activate اتمیک. از `lesson.json` دارای صوت و `lyrics[].startMs` تأییدشده بخوان؛ `.rddraft.json` هرگز در Android خوانده نمی‌شود. progress/انصراف/کمبود فضا/بازگردانی crash و نسخهٔ قبلی را مثل installer فعلی حفظ کن.
5. تصویر عمومیِ پیش‌نصب اختیاری و مستقل از فایل پوشهٔ بسته است؛ از کش تصویرِ مجاز استفاده کن. بعد از نصب، `media.cover` احرازشده در lesson در اولویت است. اگر URL تصویر خراب است، UI آهنگ و نصب audio نباید از دست برود. فقط `manifestUrl/coverUrl` در D1/کاتالوگ‌اند، نه فایل‌ها یا URL مستقیم درس/صوت.

## آزمون و تحویل Android

- آزمون JVM/دستگاه با fixtureهای **مستقل** catalog r1→r2: پس از انتشار ردیف `new-track` و refresh، کارت تازه در زبان en بدون rebuild APK ظاهر شود؛ زبان es فقط دادهٔ es (یا لیست خالی امضاشده)؛ ۳۰۴ با/بدون cache، آفلاین سرد/گرم، سوییچ زبان و حذف ردیف CMS با نصب موجود. از کلید test فقط در test/debug استفاده کن.
- Ed25519 envelope tamper/domain confusion، Base64URL padded، تکرار کلید، URL userinfo/query/HTTP/host/redirect، mismatch ID/lang با manifest و lesson، replay revision، same-version mutation، schema/کلید ناشناخته، خطای quota `1027`، خراب‌شدن cover و نبود password را با حفظ نسخهٔ قبلی تست کن. `LOCAL_PASSWORD` را با `VERIFIED` اشتباه نگیر؛ `gulum-2` bundled اثبات شبکه/امضای ناشر نیست.
- تست real Windows export جدید روی هاست واقعی مالک، `latest.json` امضاشده، نصب en/es/ko، آپدیت همان آهنگ و اضافه‌کردن آهنگ بدون APK روی API 26 و نسخهٔ جدید Android؛ UI RTL/LTR، Room migration، Media3 و starter آفلاین. **Gradle build/lint/connected tests و audit release** را انجام بده و نتایج/گیت‌های باقی‌مانده را بنویس؛ fixture/test این مخزن معادل تست اپ نیست. `docs/RELEASE.md` شاخهٔ Android guard را فقط پس از برآورده‌شدن همهٔ شرایط حذف/تعویض کند.
