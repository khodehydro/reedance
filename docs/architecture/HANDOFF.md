# متن آمادهٔ تحویل به ایجنت CMS و Android (و وابستگی Windows)

**منبع قرارداد:** همین شاخهٔ [`khodehydro/reedance/arena/e6a6294d-reedance`](https://github.com/khodehydro/reedance/tree/arena/e6a6294d-reedance)، پوشه‌های `docs/architecture/`, `contracts/v1/`, `contracts/catalog/v1/`. قبل از شروع، فایل‌ها را از **commit منتشرشدهٔ همین شاخه** بخوانید؛ `main` ممکن است هنوز قرارداد جدید را نداشته باشد. شاخهٔ Android **پروژهٔ جدا و موجود** است: [`khodehydro/reedance-android/arena/f7c293e1-reedance-android`](https://github.com/khodehydro/reedance-android/tree/arena/f7c293e1-reedance-android)، snapshot بررسی‌شده [`894a4609`](https://github.com/khodehydro/reedance-android/commit/894a4609d35eee0ec7fd6b33c96ffc5ddb1414a5). هیچ کلید خصوصی، رمز فایل، URL دارای توکن یا فایل دارای حق نشر را در چت/Git نفرستید. اینها **دستور اجرا** هستند؛ CMS/اتصال جدید Android هنوز طبق آنها پیاده‌سازی نشده‌اند.

## پیام به ایجنت CMS Cloudflare

> در همین شاخه `docs/architecture/CMS_AGENT.md` و `CATALOG_V1.md` و schema/fixtureهای `contracts/catalog/v1/` را بخوان؛ پروتکل بستهٔ `PACKAGE_V1.md`/`contracts/v1/` را تغییر نده. CMS رایگانِ **Workers Free + یک D1 Free + Access Free** را بساز: public Worker فقط `GET /v1/languages` و `GET /v1/languages/{code}/songs` برای **فهرستِ یک زبان**، admin Worker محافظت‌شده با Access برای فرم زبان‌ها و آهنگ‌ها/لینک‌ها، preview و publish نسخه‌دار/اتمیک. D1 فقط metadata (`songId`/language/title/artist/manifestUrl/coverUrl و فیلدهای نمایشی) و signed snapshots را نگه دارد. **هیچ upload/proxy/cache/download برای صوت، درس، عکس، `.rdpack` و `latest.json` روی Cloudflare ایجاد نکن**؛ فایل‌ها روی هاست HTTPS خود مالک هستند. فهرست را با Ed25519 catalog-only و domain جدا هنگام publish امضا کن، public key برای Android؛ کلید خصوصی manifest ویندوز را نگیر. Access و CSRF/allowlist host، سقف Free/monitoring و ۳۰۴/ETag/cache/fallback را درست کن. fixture test-only را در production به کار نبر. migration/test/راهنمای استقرار و انتشار مالک و نمونهٔ پاسخ API را تحویل بده؛ بدون دامنه/کلید واقعی سرویس production/رایگان نامحدود ادعا نکن.

## پیام به ایجنت Android

> **در مخزن بومیِ موجود** `khodehydro/reedance-android` (شاخهٔ معرفی‌شده توسط مالک) کار کن؛ در این مخزن جدید `android/` را از صفر نساز. ابتدا `data/LocalContentRepository.kt`, `data/AppModel.kt`, `install/PackInstaller.kt`, `install/PackInstallWorker.kt`, `contract/PackVerifier.kt`, `ui/Catalog.kt`, `data/Settings.kt`, `docs/interop/ANDROID_INSTALLER.md` را بخوان و با `docs/architecture/ANDROID_AGENT.md`, `CATALOG_V1.md`, `PACKAGE_V1.md` و fixtureهای دو قرارداد هماهنگ کن. الان کاتالوگ UI از `catalog_preview.json` همراه APK است و `pack_distribution.json.songs` URL manifest را ثابت نگه می‌دارد؛ آن را برای تولید با API امضاشدهٔ Cloudflare **فقط برای زبان انتخاب‌شده** و cache معتبر آفلاین عوض کن. WorkManager با `songId` از persisted signed snapshot URL/زبان را resolve کند؛ public key catalog `cat-` و public key manifest `sig-` و host allowlist مستقل در APK، `latest.json` و `.rdpack` را **مستقیم از هاست مالک** بگیرد. مسیر `enc-main`/رمز فایلِ Windows و Keystore، `LOCAL_PASSWORD` در برابر `VERIFIED`، hash/GCM/ZIP/schema/Room/Media3، نسخهٔ قبلی و پیشرفت را حفظ کن. کاور اختیاری فقط از هاست مالک با محدودیت دریافت؛ هیچ درسی از CMS نگیر. fixture r1→r2 باید نشان دهد **آهنگ جدید در en بدون APK جدید ظاهر می‌شود**؛ آفلاین، quota، ۳۰۴، کاتالوگ/manifest نامعتبر، زبان ناسازگار و device build را تست کن. `tr` در کد Android extension دارد ولی schema مرجع package هنوز en/es/ko؛ برای انتشار tr سازگاری نسخه‌دارِ Windows/Android را جدا حل کن. Guard انتشار را بدون آزمون/کلید/URL واقعی برندار.

## پیام به ایجنت Windows (وابستگی انتشار محتوا)

> جریان محتوا را تغییر نده: ایجنت از **متن آهنگ** یک `.rddraft.json` بی‌صوت/بی‌زمان می‌سازد؛ مالک صوت را **بعداً در Windows از سیستم خودش** برمی‌گزیند و تمام سطرها را در تایم‌لاین سینک/محتوا و حقوق را تأیید می‌کند؛ فقط سپس یک `.rdpack` رمزنگاری‌شده و `latest.json` امضاشده تولید می‌شود. خروجی immutable را **فقط روی هاست مالک** آپلود و hash/امضای remote را آزمایش کن؛ نخست pack، بعد latest. برای آهنگ جدید، فقط `songId,targetLanguage,title,artist,manifestUrl,coverUrl?` را به CMS بده، نه فایل یا کلید. پروفایل رمز فایل `enc-main` و تفاوتش با AES test fixture تاریخی را با Android هماهنگ کن؛ کلید خصوصی ناشر هرگز در Cloudflare نرود. [WINDOWS_AGENT.md](WINDOWS_AGENT.md) و [PACKAGE_V1.md](PACKAGE_V1.md) را مبنا قرار بده.

## پیام به ایجنت تولید محتوای هر آهنگ

> فقط متن لیریک، نام/زبان مقصد و اطلاعاتی که به تو می‌دهم را با [AI_CONTENT_AGENT.md](AI_CONTENT_AGENT.md)، [`draft.schema.json`](../../contracts/v1/draft.schema.json) و [نمونهٔ JSON خام](../../contracts/v1/fixtures/quiet-step.rddraft.json) به یک `<songId>.rddraft.json` آموزشی تبدیل کن. ترجمهٔ سطر/واژه، مثال/گرامر/جدول/جمله/اصطلاح و آزمون را کامل و شناسه‌ها را پایدار کن. **نه صوت، نه کاور، نه `media`, نه زمان سطرها، نه URL/CMS، نه کلید/بستهٔ رمزنگاری‌شده**. من صوت را بعداً جدا در ویندوز انتخاب و سطرها را با تایم‌لاین سینک/تأیید می‌کنم. دربارهٔ مجوز نامعلوم ادعای تأیید نساز.

## مرز مسئولیت و شرط قبول

- **CMS**: API/DB/Admin/امضای catalog-only، بدون فایل. **Android**: خواندن امن catalog و بسته/تصویر از هاست مالک در repo مستقل. **Windows**: ساخت و امضای pack/manifest و آپلود دستی روی هاست مالک. **ایجنت متن**: فقط draft. تغییر ناسازگار در `contracts/v1` نیاز به هماهنگی و نسخهٔ جدید دارد؛ `contracts/catalog/v1` مستقل است و برای تغییر ناسازگار catalog/v2 بسازید.
- تحویل واقعی فقط با دو آزمون مستقل: (۱) خروجی تازهٔ Windows از متن→انتخاب صوت/سینک → هاست مالک → Android نصب/پخش آفلاین و آپدیت همان آهنگ؛ (۲) ردیف آهنگ **کاملاً جدید** در CMS publish شود → بدون rebuild APK روی Android ظاهر و با manifest امضاشده نصب شود. فقط fixture، تست وب یا کارت preview این شروط را ثابت نمی‌کند.
- مالک باید دامنه/هاست واقعی، بودجه/سقف ترافیک هاست، مجوز صوت/متن/کاور و public key/secret management را فراهم کند؛ service در سهمیهٔ Free اختلال می‌گیرد، cache محلی و فایل نصب‌شده باید کار کنند. تغییر زبان ناشناخته/کلید جدید ممکن است به APK جدید نیاز داشته باشد.
